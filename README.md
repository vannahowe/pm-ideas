# 产品经理的需求灵感库

用 GitHub Issue 沉淀需求灵感、产品观察和思考，让零散的想法变成可积累、可追溯的资产。

## 这个仓库是干嘛的

产品经理每天冒出大量想法：用户的吐槽、竞品的做法、某个流程的不顺、一个还没成型的点子。它们大多聊完就忘。这里用 Issue 把每条想法记下来、分类、追踪状态，日积月累就是一份个人产品思考档案。

## 怎么用

每条想法开一个 Issue。标题一句话说清，正文按下面的模板填。用标签（Label）分类和标记状态。

### 标签体系

按「来源域」分类：

- `idea` 产品点子 / 功能设想
- `pain-point` 用户痛点 / 体验问题
- `competitor` 竞品观察
- `data` 数据异常 / 业务现象
- `vision` 长期思考 / 方向判断

按「状态」标记：

- `status:inbox` 刚记录，还没想清楚
- `status:validating` 正在验证价值
- `status:adopted` 已被采纳 / 进入需求池
- `status:parked` 暂时搁置

### Issue 模板

```
## 一句话描述
（这个想法是什么）

## 来源
（用户反馈 / 数据观察 / 竞品 / 自己想到的）

## 为什么值得做
（解决什么问题，对谁有价值）

## 粗略方案
（能想到怎么做就写，想不清楚就留空）

## 后续动作
（下一步要验证什么）
```

## 维护节奏

- 想到就记，不追求写完整
- 定期回看 `status:inbox`，做一次筛选
- 被采纳的想法打上 `status:adopted`，留个交代
